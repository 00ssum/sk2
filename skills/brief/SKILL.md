제출물 확정 전에만 쓴다. 확정 후에는 쓰지 않는다. 파일로 저장하지 않고 화면에만 출력한다.

NOTES.md, DECISIONS.md, 실제 코드, git log만 근거로 아래를 1쪽으로 정리한다. 기록에 없는 것을 지어내지 않는다.

1. 한 문장: 무엇을 만들었고 무엇을 안 했나
2. 구조: 입력 → 처리 → 출력. 파일·함수 이름으로
3. 핵심 결정 3개: 결정 / 근거 / 버린 대안
4. 검증한 것: 명령과 결과. 검증 못 한 것: 이유
5. 가장 약한 부분 하나: 어떤 입력에서 틀리나
6. AI가 한 일 / 내가 판단한 일
7. 예상 질문 6개와 답의 핵심 키워드 (문장 답안은 쓰지 않는다)
8. 질문의 전제가 실제 구현과 다를 수 있는 지점

핸드오프로 쓸 때는 7·8 대신 "다음 할 일 1~3개"와 "절대 어기면 안 되는 제약 3개"를 적는다.
